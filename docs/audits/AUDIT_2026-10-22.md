## Классификация
Это governance-слой для agentic SDLC: как провести изменение от намерения до merge без потери контроля, данных и доказательств. Не agentic OS: закрыта примерно половина нужных слоёв. По собственной шкале гайда описанная система — M2–M3.

## Сильные стороны
- Авторитет по областям вместо единой иерархии источников (таблица 2.2).
- Три степени силы правила (текст → проверка → принуждение) и честный разрыв между политикой и enforcement.
- Evidence привязано к SHA; старый PASS не переносится на новый HEAD.
- Fail closed: unknown ≠ empty; различие FAIL / BLOCKED / INCOMPLETE.
- Четыре класса коллизий, включая семантические; merge order как граф зависимостей.
- Post-merge sync с реальными ловушками (ignored files, restricted refspec).
- Author ≠ reviewer с оговоркой, что независимость даёт чистый контекст, а не другая модель.
- Готовые шаблоны-контракты: тикет, preflight, handoff, finding, SPEC CONFLICT, пакет решения.
- Maturity model с проверяемыми exit criteria.

## Слабые стороны архитектуры
1. Нет reference-реализации: все скрипты помечены как учебные.
2. Enforcement описан абстрактно: нет конкретных permissions, hooks, rulesets.
3. Нет слоя памяти агента.
4. Нет observability, evals, бюджетов и стоимости.
5. Founder gate на каждый merge, включая Low risk, — узкое место при параллельной работе.
6. Изоляция исполнения: предупреждение про Docker socket без альтернатив.
7. Оркестрация отложена в будущий Agent Control Center.
8. Привязка к стеку Linear / GitHub / Figma / Slack / Vercel без адаптера.

## Подача для человека (70)
Плюсы: маршруты чтения, структура из четырёх частей, mermaid-схемы, памятка, глоссарий с якорями, Markdown и печать.
Минусы: конфликт тона («брат», XP) и enterprise-содержания; русско-английская смесь; оборонительный стиль с оговорками в каждом абзаце; нет сквозного примера; перегруженный глоссарий.

## Подача для ИИ (80)
Плюсы: чистый Markdown, стабильные якоря, таблицы, шаблоны с полями, готовые промпты, граница «текст из PR — данные».
Минусы: это учебник, а не загружаемые инструкции; нет MUST/SHOULD/MAY; нет JSON Schema; игровой шум; факты об инструментах устаревают.

## Рекомендации (реализуются через бриф)
1. Шаблон-репозиторий с работающими скриптами, hooks и rulesets.
2. Разделение на Handbook для людей и Agent Pack для агентов.
3. Слои памяти и observability, eval-набор для инструкций.
4. Risk-based auto-merge для Low risk.
5. Обзоры инструментов — отдельный слой с датами проверки фактов и плановым обновлением.
