# Parity audit: ChatGPT Sites (version 20) and Vercel preview — 2026-10-22

Ticket P1-08 (https://github.com/Makkov-Office/vibe-coding-guidebook/issues/10). Read-only: GET requests and a headless browser; nothing was changed on ChatGPT Sites or in the Vercel settings.

**In plain words.** We are moving from one house (ChatGPT Sites) to another (Vercel), and we checked that in the new house everything stands in the same places: the same books on the same shelves, the switches work, the doors open. We compared 30 pages on a phone and on a large screen: the images matched (with a tolerance for anti-aliasing), the text and bookmarks matched completely, search, term hints, experience points and the print version work the same way. Only small things differ, which we ourselves fixed earlier with your consent (where the cursor jumps after search and the menu, what is visible without JavaScript, when the site preloads chapters). There are no new visual differences between the houses. But we found an old breakage, the same in both houses: the "not found" page (a broken link) shows an empty error screen instead of a sign with the menu. Whether to fix it before switching the new site on for everyone is your decision (B1); switching on production is also a separate decision.

## How it was checked

Environment: a Claude Code cloud session, Node 22.22.0, Chromium 1194 (`/opt/pw-browsers`), `reducedMotion: reduce`. First runs 2026-10-22 19:50–20:41 UTC; the final data in this directory is a repeat run on 2026-10-23 00:53–01:07 UTC (after the independent review) against the same deploy.

1. `npm ci` and `npm run validate` on `e36fb13`: PASS (content, test, typecheck, lint, build, tree).
2. `CHECK_COOKIE=… node scripts/check-vercel-output.mjs --url <new>` → `check-vercel-output: PASS {"checks":155,"pass":155,"fail":0}`.
3. `CHECK_COOKIE=… node scripts/parity-audit.mjs --old <old> --new <new> --out docs/audits/parity-2026-10-22` → `pages: 30, text equal 29, ids equal 30`, `empty on both sides (vacuous): /nope`, `client error screen: old /nope; new /nope`, `screenshots: 60 compared, identical 60`, `errors: 0`. Comparing empty sides does not count as text equality: `/nope` shows an error screen on both sites (B1). Full data: [`parity-2026-10-22/parity.json`](parity-2026-10-22/parity.json) (the `note` field holds the revisions and deployment id); the output of step 2: [`parity-2026-10-22/check-vercel-output.json`](parity-2026-10-22/check-vercel-output.json).

On every page `parity-audit.mjs` waits for hydration (the `js-enabled` class, enabled search and "Chapter studied" buttons), fonts and all images (lazy → eager, scrolling), then takes a full screenshot of both sites and compares the pixels (threshold 24 per channel). A page that does not come alive within 20 s is reloaded (up to 3 times); this is recorded in `hydration`.

Full screenshots are compared (PNG in memory, not committed). The committed WebP files only illustrate the first screen: lossy compression, so their bytes for old and new may differ when the PNGs are equal. First-screen screenshots of both sites (WebP): [`parity-2026-10-22/shots/1440/`](parity-2026-10-22/shots/1440/) and [`parity-2026-10-22/shots/360/`](parity-2026-10-22/shots/360/), name `<route>.<old|new>.webp` (`index` is the home page, `chapters-01` is `/chapters/01`, `nope` is the 404). There is no `diff/` directory: no differences were found on full pages.

## Differences

### Expected (founder decision, #28 / P1-12)

- **E1.** Focus after closing search: on the search button, not on `body` (fix R1).
- **E2.** Focus after choosing a chapter in the drawer: on the new page, not on the menu button.
- **E3.** No-JS HTML without a skeleton: a chapter is readable without JavaScript (fix R2).
- **E4.** A client skeleton at the 500 ms threshold and prefetch on intent instead of prefetching all visible links.

### New

- **D1. `/handbook.md`: one byte.** On Sites the file is 265 802 bytes and ends with `\r\n`; on Vercel it is 265 801 bytes, `\n`, byte-for-byte `content/handbook.md` (as in `a99332c`). Without the `\r` the text is equal. That is, Sites holds not quite the same file as the repository; Vercel serves the source. Content-Type: Sites `text/markdown`, Vercel `text/markdown; charset=utf-8`. Impact on the reader: none. No decision needed.
- **D2. HTTP headers (not visible to the reader).** Sites: HTML `no-store, must-revalidate`, gzip. Vercel: `public, max-age=0, must-revalidate`, Brotli, HSTS, `/_next/static/*` `immutable` for a year. On preview Vercel adds `X-Robots-Tag: noindex`: this is a property of preview, it will not be on production; check when production is switched on.
- **D3. The old site sometimes "comes alive" slowly.** In the run of 2026-10-22 20:23–20:41 UTC, 2 Sites loads (`/chapters/11` and `/chapters/22`, 360 px) did not hydrate within 20 s, but did on the second attempt; in the final run of 2026-10-23 there were 0 such cases, and Vercel had 0 in all runs. Earlier runs on Sites also had: `page.reload` of `/glossary` did not reach `load` within 30 s (`check-vercel-output --url` against Sites was aborted), one SPA transition became a full load, 2–3 screenshots were taken before hydration (the script did not wait for it then). This is a property of Sites, not a Vercel regression; that is why a full `check-vercel-output` for Sites as a baseline was not obtained.

### A common breakage on both sites (not a difference; a founder decision is needed)

- **B1. The 404 page falls into an error screen.** The server returns a normal 404 page (HTTP 404, header, navigation, the text "404: This page could not be found"). After JavaScript loads, `ContextPreview` calls `observer.observe(document.getElementById('reader')!)`, the 404 has no `#reader`, and the exception `Failed to execute 'observe' on 'MutationObserver': parameter 1 is not of type 'Node'` crashes the app: the reader sees the framework screen "This page couldn’t load" with Reload/Back buttons, without the header, menu and search. The same on both sites, both widths (`shots/*/nope.*.webp`, `parity.json` → `pages["/nope"].errorScreen`), so parity holds, but anyone arriving via a broken link sees an error. The fix (a `null` check before `observe`) is outside the scope of P1-08; a founder decision is requested: fix it in a separate ticket before switching on production (recommended) or after.

- Tooltips of type `popover` and the terms side panel (`panel`): on `/chapters/01` the first 6 terms are `tooltip`.
- Chromium only; no Safari, Firefox or real mobile devices. Keyboard navigation: only Ctrl K, Enter, Esc.
- Vercel production does not exist (switched off, ADR-0002); `noindex`, cache and the production domain — when it is switched on.
- The Sites version number "20" was not confirmed from outside (see above).
