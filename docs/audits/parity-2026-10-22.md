# Parity-аудит: ChatGPT Sites (версия 20) и Vercel preview — 22.10.2026

Тикет P1-08 (https://github.com/Makkov-Office/vibe-coding-guidebook/issues/10). Только чтение: GET-запросы и headless-браузер; на ChatGPT Sites и в настройках Vercel ничего не менялось.

**Простыми словами.** Мы переезжаем из одного дома (ChatGPT Sites) в другой (Vercel) и проверили, что в новом доме всё стоит на тех же местах: те же книги на тех же полках, выключатели работают, двери открываются. Сравнили 30 страниц на телефоне и на большом экране — картинки совпали (с допуском на сглаживание), текст и закладки совпали полностью, поиск, подсказки к терминам, очки опыта и версия для печати работают одинаково. Отличаются только мелочи, которые мы сами исправили раньше с твоего согласия (куда прыгает курсор после поиска и меню, что видно без JavaScript, когда сайт заранее подгружает главы). Новых визуальных расхождений между домами нет. Но нашли старую поломку, одинаковую в обоих домах: страница «не найдено» (битая ссылка) вместо таблички с меню показывает пустой экран ошибки. Чинить ли её до включения нового сайта для всех — твоё решение (B1); включение production — тоже отдельное решение.

## Расхождения

### Ожидаемые (решение founder, #28 / P1-12)

- **E1.** Фокус после закрытия поиска: на кнопке поиска, а не на `body` (исправление R1).
- **E2.** Фокус после выбора главы в drawer: на новой странице, а не на кнопке меню.
- **E3.** No-JS HTML без скелетона: глава читается без JavaScript (исправление R2).
- **E4.** Клиентский скелетон по порогу 500 мс и prefetch по намерению вместо prefetch всех видимых ссылок.

### Новые

- **D1. `/handbook.md`: один байт.** На Sites файл 265 802 байта и заканчивается на `\r\n`, на Vercel — 265 801 байт, `\n`, байт-в-байт `content/handbook.md` (как и в `a99332c`). Без `\r` текст равен. То есть на Sites лежит не совсем тот файл, что в репозитории; Vercel отдаёт исходник. Content-Type: Sites `text/markdown`, Vercel `text/markdown; charset=utf-8`. Влияние на читателя — нет. Решение не требуется.
- **D2. Заголовки HTTP (не видно читателю).** Sites: HTML `no-store, must-revalidate`, gzip. Vercel: `public, max-age=0, must-revalidate`, Brotli, HSTS, `/_next/static/*` — `immutable` на год. На preview Vercel добавляет `X-Robots-Tag: noindex` — это свойство preview, на production его не будет; проверить при включении production.
- **D3. Старый сайт иногда «оживает» медленно.** В прогоне 22.10 20:23–20:41 UTC 2 загрузки Sites (`/chapters/11` и `/chapters/22`, 360 px) не гидратировались за 20 с, со второй попытки — да; в итоговом прогоне 23.10 таких случаев 0, у Vercel — 0 во всех прогонах. В более ранних прогонах на Sites было ещё: `page.reload` `/glossary` не дождался `load` за 30 с (`check-vercel-output --url` против Sites прервался), один SPA-переход стал полной загрузкой, 2–3 скриншота сняты до гидратации (тогда скрипт ещё не ждал её). Это особенность Sites, не регрессия Vercel; поэтому полный `check-vercel-output` для Sites как baseline не получен.

### Общая поломка обоих сайтов (не расхождение, нужно решение founder)

- **B1. Страница 404 падает в экран ошибки.** Сервер отдаёт нормальную страницу 404 (HTTP 404, шапка, навигация, текст «404: This page could not be found»). После загрузки JavaScript `ContextPreview` вызывает `observer.observe(document.getElementById('reader')!)`, у 404 нет `#reader`, и исключение `Failed to execute 'observe' on 'MutationObserver': parameter 1 is not of type 'Node'` роняет приложение: читатель видит экран фреймворка «This page couldn’t load» с кнопками Reload/Back, без шапки, меню и поиска. Одинаково на обоих сайтах, обе ширины (`shots/*/nope.*.webp`, `parity.json` → `pages["/nope"].errorScreen`), то есть паритет сохранён, но любой, кто пришёл по битой ссылке, видит ошибку. Исправление (проверка на `null` перед `observe`) — вне scope P1-08; решение founder запрошено: чинить отдельным тикетом до включения production (рекомендация) или после.
