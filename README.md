# ULTIMATE Vibe-coder guidebook [BETA]

Русскоязычный учебный портал для брата: 22 учебные главы, orientation 00 и единый глоссарий (394 определения / 11 тем), 6 Mermaid-схем. React, TypeScript, Vinext и npm lockfile; native Sites starter. Учебные данные компилируются при сборке, текст текущей страницы входит в первоначальный HTML. Backend, аккаунты, аналитика и агентный runtime не добавлены.

## Запуск и проверка

Node.js 22.x не ниже 22.13 (`engines` `^22.13.0`) и npm (эталонная версия — `.nvmrc`, например `nvm use`): `npm ci`, затем `npm run dev`. Адрес выводится в терминале. Production: `npm run build`, затем `npm start`.

- `npm run doctor` — проверка среды: Node против `engines` и `.nvmrc`, npm, согласованность `package.json` / `package-lock.json` / `node_modules`, ветка и чистота git, Chrome для Mermaid. FAIL (exit 1) — неподходящий Node или `node_modules` не совпадает с lockfile; WARN — работа в `main`, грязное дерево, Node не равен `.nvmrc`, нет Chrome при переиспользуемых SVG.
- `npm run validate` — одна точка входа для проверки проекта: `content`, `test`, `typecheck`, `lint`, `build` последовательно; первый FAIL останавливает остальные (SKIP). Затем validate сравнивает `git status` до и после: любое новое изменение (устаревшие сгенерированные файлы, новые неотслеживаемые) — FAIL, исключений нет. Кэш `typecheck` (`tsconfig.tsbuildinfo`, `incremental: true`) не отслеживается git и игнорируется (`*.tsbuildinfo` в `.gitignore`). Exit 0 только при общем PASS.
- CI (GitHub Actions, `.github/workflows/ci.yml`, check `validate`) — на каждом pull request с любой base и на push в `main`: Node из `.nvmrc`, `npm ci`, `npm run validate`, затем `node .github/scripts/check-diagram-assets.mjs` и загрузка `dist` как artifact `dist-<SHA>` (14 дней). В CI нет Chrome: если схема новая или изменилась, а SVG не закоммичен, `render-diagrams` пишет в manifest `error`, и CI падает на проверке SVG (либо на шаге `tree`). Отрендерите схему локально с Chrome и закоммитьте `public/diagrams/*.svg` и `src/content/diagram-assets.json`. Права workflow — `contents: read`, секреты не используются; новый push в PR отменяет устаревший run, runs на `main` не отменяются. Смена base PR без push CI не перезапускает: после retarget нужен push (например, merge новой base в ветку).
- CI, check `e2e` — после `validate` в том же run: `npm ci`, скачивает artifact `dist-<SHA>` (тот же `dist`, без второй сборки), ставит Chromium Playwright (`npx playwright install --with-deps --no-shell chromium`), запускает `npm start` в фоне и ждёт ответа `http://127.0.0.1:8787/` (до 90 с), затем `npm run test:e2e -- --forbid-only --add-reporter=html`. Любой упавший тест — красный check. Artifact `e2e-report-<SHA>` (14 дней, загружается и при падении): HTML-отчёт `playwright-report/` (`npx playwright show-report playwright-report`), `docs/browser-results.json`, trace упавших тестов в `.sites-runtime/playwright/` (открыть: `npx playwright show-trace <trace.zip>`) и лог сервера `e2e-server.log`. Браузер в CI — `HANDBOOK_BROWSER_CHANNEL=chromium`: Chromium той ревизии, что закреплена `@playwright/test` в lockfile, в new headless mode; локально по умолчанию по-прежнему Microsoft Edge. Браузеры не кэшируются: по документации Playwright восстановление кэша занимает столько же, сколько скачивание, а системные зависимости Linux (`--with-deps`) не кэшируются; кэшируется только npm (`setup-node`). Время (замер 22.10.2026, `ubuntu-24.04`): зелёный job e2e ≈ 3,5 мин — `npm ci` ≈ 30 с, установка Chromium с зависимостями 19–87 с, тесты ≈ 1 мин; тест, падающий по timeout, добавляет до 60 с; timeout job 30 мин. `e2e` стартует после `validate` (≈ 1 мин 45 с). Если `validate` упал, `e2e` пропускается.

- `npm run content` — AST/GFM, allowlist HTML, glossary/search/anchors, independent coverage audit.
- `npm test` — content/download parity, оригинальные SHA256, inventory, targets, sanitization, appendix rejection, longest-match и preview threshold.
- `npm run typecheck` и `npm run lint`.
- `npm run test:e2e` — Playwright / установленный Microsoft Edge. Нужен запущенный сервер; `HANDBOOK_URL` задаёт другой адрес (по умолчанию localhost:3000; `npm start` слушает `http://127.0.0.1:8787`). `HANDBOOK_BROWSER_CHANNEL` задаёт другой channel Playwright (в CI — `chromium`).
- `npm run build` — production Worker build и автоматический `postbuild` audit public/dist на приватный provenance и implementation appendix.

PowerShell для текущего dev-порта: `$env:HANDBOOK_URL='http://127.0.0.1:5173'`, затем `npm run test:e2e`.

## Контент

Редактируйте `content/handbook.md`: это источник учебного текста, определений и скачиваемого Markdown. Слой «Обзор» глав с табами — `content/overview/NN.md` (раздел «Табы и слой «Обзор»» ниже). Родительские исходники сохранены без изменений; их SHA256 находятся в `docs/original-source-hashes.json`. После согласованной редакторской очистки учебный source намеренно отличается от исходного документа.

Результаты компиляции: `src/content/generated.json`, `public/handbook.md`, `docs/coverage-report.json`. Скачиваемый Markdown точно совпадает с учебным source. Главная `/`, главы `/chapters/01`–`/chapters/22`, глоссарий `/glossary`, весь раскрытый материал `/print`.

Обзоры инструментов: `/tools`, `/tools/codex`, `/tools/claude-code`. Они написаны в том же `content/handbook.md`, включены в поиск, Markdown и печать, но не меняют маршрут и прогресс 22 глав. Матрицы подписок и доступность возможностей проверены 11 октября 2026 по официальным источникам; research notes: `docs/codex-research.md` и `docs/claude-code-research.md`. При обновлении проверяйте документацию, releases, цену и ограничения каждого клиента отдельно, затем меняйте видимую дату проверки.

Дополнительный материал помечайте парными HTML-комментариями `<!-- details: Название -->` и `<!-- /details -->`. Compiler сначала размечает и индексирует отдельные блоки, затем оборачивает их в `<details>`: поиск и canonical anchors продолжают работать внутри закрытых блоков. Обязательные шаги и предупреждения оставляйте снаружи.

Glossary registry извлекается из главы 23. Определения до 160 видимых символов, состоящие из одного обычного абзаца, получают tooltip; короткие определения с официальной ссылкой — немодальный popover, длинные/структурированные — panel. Сервисы, локальные инструменты и библиотеки обозначены явно; ссылки открываются в новой вкладке. Название и aliases не входят в подсчёт. Все нынешние определения короткие; длинная ветка проверяется отдельной браузерной fixture без изменения production текста.

Автоссылки сохраняются для всех подходящих вхождений. Словоформы и неоднозначности: `src/content/term-overrides.mjs`. Compatibility registry `block-identities.json` сохраняет IDs неизменённых блоков, `practice-identities.json` — прежние ключи чеклистов. Новые блоки получают отдельный namespace. После редактирования проверьте overrides, targets и **0 unexplained gaps**. Coverage включает динамические evidence/owner panels и definitions previews с явным исключением рекурсивной разметки. Raw executable source защищён; Copy возвращает исходник из registry.

## Карта адресов

Новая структура (P2-05, план RD-01, ADR-0003): 9 разделов rail — Главная `/`, Начать `/start`, Основы `/base`, Процесс `/flow`, Контроль `/control`, Надёжность `/reliability`, Практика `/practice`, Инструменты `/tools`, Agent Pack `/agents`; вне rail — Справочник `/reference` (памятка 22, глоссарий). Глава — `/<раздел>/<NN-slug>`, её 4 таба — сегменты пути, не query: Обзор — сам адрес главы, Как устроено `/how-it-works`, Как применять `/apply`, Проверь себя `/check` (например `/flow/08-preflight/apply`).

`src/content/url-map.json` — машиночитаемая карта, правится руками (это не сгенерированный файл). Запись `pages[]`: `old` (нынешний адрес), `new` (куда переезжает содержимое), `section`, `chapter` (id из `generated.json`); у глав с табами — `tabs: true`, `lead` (таб для текста до первого подзаголовка) и `anchors`: каждый подзаголовок и интерактивная панель главы → таб. Остальные якоря (блоки, вхождения терминов) идут за подзаголовком, под которым стоят; id главы — Обзор. `keep: true` — старый адрес остаётся живой страницей с другим содержимым (`/` → Главная, а вводная 00 уходит в `/start/00-how-to-read`); `alias: true` — старый адрес, которого сейчас нет в сборке (`/chapters/23`). Логика — `scripts/url-map.mjs`.

Редиректы включаются сами, по мере переезда, без флага: `scripts/vercel-output.mjs` добавляет 308 `old → new` (и для формы со слэшем, один переход) только для записей, чья новая страница уже есть в сборке; до этого старый адрес отвечает 200, как раньше. Сборка Vercel падает, если в ней есть страница, которой нет в карте, и если реестр якорей ещё указывает на старый адрес, который в этой сборке уже редиректит (иначе Reader вернёт старую ссылку на старый адрес, 308 — обратно на Обзор: петля). `npm test` (`tests/url-map.test.mjs`) проверяет: каждый маршрут сборки, каждая статическая страница `app/**/page.tsx` и каждая глава есть в карте; каждый подзаголовок и панель главы имеют таб, лишних якорей нет; все якоря из `generated.json` находят новую страницу; нет цепочек, циклов и совпадающих адресов; никто не переезжает на `/` или корень раздела, служебные страницы (`service`) адрес не меняют; сломанные записи ловятся. `check-vercel-output.mjs` проверяет каждую запись по HTTP: 308 на существующую цель или 200, пока цели нет. Якорь на старом адресе после 308 сохраняется браузером; если его нет на странице, Reader ищет его в реестре якорей (`public/data/anchors-*.json`) и переходит на указанную там страницу (`Reader.tsx`, восстановление старых ссылок). Реестр строит компилятор; когда глава переезжает (P5), путь якоря в реестре берите из `resolveAnchors` карты, тогда старая ссылка приводит на нужный таб.

Как добавить или перенести страницу: новая страница (в том числе `app/<путь>/page.tsx`) — запись `pages[]` (для нового адреса без прошлого `old` = `new`, служебная — `section: "service"`); новый подзаголовок в главе с табами — строка в её `anchors`, иначе `npm test` упадёт; переименование подзаголовка меняет его id — поправьте ключ в `anchors`. Когда новая страница появляется в сборке, старый адрес начинает редиректить сам; старый маршрут уберите из сборки в том же PR, иначе он недостижим, а реестр якорей переведите на `resolveAnchors`, иначе сборка упадёт.

## Табы и слой «Обзор»

Формат P5-01 (бриф 8.1–8.2). Глава 01–21 собирается в 4 таба. Компилятор (`src/content/compiler.mjs`, опция `urlMap`) раскладывает текст главы из `content/handbook.md` по табам по той же карте `src/content/url-map.json`: блок идёт в таб подзаголовка `###`, под которым стоит, текст до первого подзаголовка — в таб `lead`, заголовок главы — в `heading` для hero. Каждый блок попадает ровно в один таб, ничего не сокращается. Блок `<!-- details: -->`, который захватывает подзаголовки разных табов, и подзаголовок без таба в карте — FAIL сборки. В `generated.json` у такой главы: `heading`, `tabs[]` (`id`, `html`, `outline`, `panels`) и `overview`. `html` главы целиком пока остаётся для нынешних страниц. У записей поиска глав с табами есть поле `tab`; пути поиска и якорей не меняются до P5-03.

Слой «Обзор» — файл `content/overview/NN.md` (`NN` — номер главы с табами). Шаблон обязателен, компилятор проверяет каждое правило и падает с именем файла:
- frontmatter: ровно `chapter` (совпадает с `NN`), `title`, `minutes` (целое > 0), `rule_strength` (`MUST`, `SHOULD` или `MAY`), каждый ключ один раз, значение без кавычек или в парных двойных; BOM и CRLF допустимы;
- только разделы `##`, ровно и по порядку: Зачем, Правило (правило — одной непустой цитатой `>`), Как это выглядит, Три вещи, которые нужно сделать (только нумерованный список из 3 непустых пунктов), Частая ошибка, Проверь себя; пустой раздел — FAIL;
- не больше 350 слов, 1 таблицы и 1 схемы Mermaid; без HTML и `<!-- details -->`.

Обзор проходит тот же конвейер, что и текст главы: санитизация, автоссылки на глоссарий, блоки кода, поиск (`tab: 'overview'`), coverage audit. Id блоков — `ch-NN-overview-*`; на них можно ссылаться (`[Правило](#ch-NN-overview-правило)`), в реестр старых якорей `anchors` они не входят. Запись поиска заголовка главы получает `tab: 'overview'`, как и сам id главы в карте адресов. Обзор стоит первым в табе «Обзор». Пока файла нет, таб «Обзор» пустой: тексты пишут P5-04 и P6, их принимает агент-редактор (бриф 9.5). `docs/coverage-report.json` → `tabs`: число глав с табами, разложенных блоков и обзоров. Тесты — `tests/content-tabs.test.mjs` (fixture `tests/fixtures/overview-08.md` только для теста, на сайт не попадает).

## Уровни глоссария

`content/glossary-levels.json` (P6-07) — уровень каждого термина раздела 23: `basic` («Базовое») — общий словарь разработки, термин значит то же самое вне руководства (Git, GitHub, среда, тесты, веб-форматы, сервисы); `professional` («Профессиональное») — термины метода агентной инженерии и строгие формулировки руководства, даже если слово известно и вне него (роли, состояния задачи, evidence и проверки, риск и безопасность, параллельная интеграция, события и контроль агентов). В `terms` у каждой темы (`"23.3"`) два списка id; каждый термин стоит ровно в одном списке своей темы, иначе `npm run content` падает с именем термина. `collapsed` — темы и подпись группы, в которую собраны их базовые термины в конце темы (сейчас Git, `23.3`); переход по `#term-*`, поиск, фильтр «Базовое» и `/print` её раскрывают. Компилятор пишет `level` в `GlossaryTerm` и `data-level` на карточку; определения, anchors и поиск от уровня не зависят. Новый термин в `content/handbook.md` требует записи в этом файле. Классификацию проверяет агент-редактор (бриф 9.5). Тесты — `tests/glossary-levels.test.mjs`, `tests/browser/glossary-levels.spec.ts`.

## Чтение и обучение

При JavaScript термины открывают пояснение рядом; без JavaScript это canonical glossary links. Tooltip не меняет scroll, URL или history. Подсказка и панель термина показывают его уровень. Длинные определения и два шаблона (глава 06 / глава 14) используют немодальный desktop drawer / модальный mobile sheet. Явный переход в глоссарий сохраняет точный origin для возврата.

Прогресс локален и живёт в одном ProgressStore (`src/components/progress-store.mjs`, P7-01): ключ `mae-progress`, запись `{version: 2, completed, exercises, practice, reading}`. Главы и позиция чтения хранятся по стабильным id страниц и табов из `src/content/url-map.json` (`ch-08`, таб `apply`), а не по адресам, поэтому переезд страниц прогресс не теряет. API: `get()`, `set(update)` (false, если хранилище отказало), `subscribe(listener)`, `unavailable()`, `damaged()`. Миграция v1 → v2 выполняется один раз при первом чтении: `handbook-learning-v2` (главы и упражнения), `handbook-reading-v2` (последняя страница и scroll), `practice:*` (чеклисты) и самый старый `handbook-progress` (глава открывается с начала: прежняя абсолютная координата не применима). Каждая часть читается отдельно, битая пропускается, интерфейс сообщает об этом. Старые ключи остаются на месте (запасная копия на случай отката) и больше не пишутся. Тесты: `tests/progress-store.test.mjs` (фикстура `tests/fixtures/progress-v1-main.json` снята с реальной сессии на `main`) и `tests/browser/progress-migration.spec.ts`. Есть явное продолжение, отмена completion, четыре достижения и сброс. При отказе localStorage отметки сохраняются в памяти между страницами до перезагрузки вкладки; интерфейс сообщает об этом. При отказе clipboard исходник можно скопировать вручную.

## Скорость и учебный профиль

Общий интерфейс находится в `app/(reader)/layout.tsx` и сохраняется при переходах через Link. Страница передаёт только собственные определения, outline и исходники примеров через ReaderPageData. Поиск и совместимость старых anchors — отдельные файлы `public/data/` с hash в имени: поиск загружается при открытии, registry — только для старой неразрешённой ссылки. Pending-переход показывает индикатор, а если он длится дольше 500 мс — скелетон на месте страницы; reduced motion отключает декоративное движение. Скелетон клиентский (`Reader`), без `loading.tsx`: такая граница Suspense выносила текст страницы из первоначального HTML в скрытый блок, и без JavaScript была видна только заглушка (P1-12). Ссылки шапки, sidebar и drawer prefetch'ат маршрут по намерению (наведение, фокус, касание), а не при появлении на экране.

`npm run content` также генерирует static SVG Mermaid и ленивые assets. SVG переиспользуется при совпадении source/config hash. Для новой или изменённой схемы нужен Chrome: Windows использует установленный Google Chrome, другую среду настройте через `MERMAID_CHROME_PATH`. Browser renderer не включается в client bundle. Ошибка отдельной схемы раскрывает текст и показывает диагностику. Учебный Markdown остаётся единственным источником схем.

Сборка включает native Vinext prerender; HTML/RSC artifacts находятся в `dist/server/prerendered-routes/`. Reader routes используют штатный static cache. Не добавлен ручной response cache поверх Sites access control. Prerender Node seeding не следует считать доказательством cache hit на холодном production Worker: фактические локальные headers и ограничения записаны в implementation notes.

Профиль вычисляет XP из существующих отметок: глава +100, упражнение +50, максимум 2450. Четыре уровня, четыре знака за группы глав и добровольный знак за упражнения. Повторная отметка не приносит дополнительные очки, отмена уменьшает XP. Новых аккаунтов, quizzes, штрафов за пропущенные дни и обязательных заданий нет. Screenshots: `learning-profile-desktop.jpg`, `learning-profile-mobile.jpg`.

Главная навигация: вложенные списки под «Навигация» в content/handbook.md задают пять групп; compiler формирует карточки с иконками и обычными ссылками. Оформление — src/design/home-route.css, быстрые переходы — существующий Reader. Сохранён прежний anchor ch-00-b1006. Screenshots: home-navigation-desktop.jpg и home-navigation-mobile.jpg.
