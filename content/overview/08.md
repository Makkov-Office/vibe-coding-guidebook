## Зачем
Проверка перед стартом (preflight) не даёт агенту начать работу по устаревшей задаче, в чужой папке или поверх чужих изменений.

## Правило
> Реализацию начинают только после результата PASS.

## Как это выглядит
Агент берёт в работу DEMO-42: поиск по названию в каталоге. Перед первой правкой он пишет короткий отчёт:

```text
Ticket: DEMO-42, Todo
Base: origin/main at <actual full SHA>
Local state: clean in task worktree
Collisions: file overlap only with DEMO-43; shared index reviewed
Result: PASS
```

Это сокращённый отчёт: полный шаблон — по ссылке ниже. Значения в угловых скобках берут из настоящих проверок, а не придумывают.

## Три вещи, которые нужно сделать
1. Получить актуальную задачу: статус, зависимости и исходные документы. Прочитать правила и документацию репозитория.
2. Проверить своё рабочее место: репозиторий, ветку и локальные изменения. Безопасно обновить сведения о main и записать base SHA.
3. Оценить риск, влияние на документацию и пересечения с другими задачами и открытыми PR.

## Частая ошибка
Считать, что нет данных — значит всё чисто. Недоступный diff не пустой, а недоступный список PR не значит, что PR нет. Такая проверка останавливается и называет причину: FAIL, BLOCKED и INCOMPLETE — это не PASS.
